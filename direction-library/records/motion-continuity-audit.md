# モーション継続性の実測検品 / Motion Continuity Audit

## 概要
「なんか止まって見える」を主観で潰さず、**フレーム間差分エネルギーを実測して**止まっているカットを特定する検品手法。参考動画があるなら同じ指標で並べると、どのショットがどれだけ足りないかが数値で出る。静止画素材のMVで最も起きやすい事故＝「カットは変わるのに画が死んでいる」を確実に捕まえる。

## 主な用途
- 静止画素材／ループ素材で組んだMVのレンダー検品
- 参考動画を再現するときの「流れ」の合わせ込み
- 長尺（3〜5分）で中だるみしている区間の特定
- 最終ホールド・アウトロが「フリーズに見える」かの判定

## 演出内容

### 指標
10fps・320×180・グレースケールに落として、**隣接フレームの平均絶対差** `mean|frame[i] - frame[i-1]|` を出す。単位は0〜255の輝度レベル。

```python
# fps=10, 320x180, gray に展開してから
d = [np.abs(A[i] - A[i-1]).mean() for i in range(1, len(A))]
```

解像度を落とすのが肝。フルHDのままだと**細かいグレインだけで数値が立ち**、「画は止まっているがノイズは動いている」を見逃す。逆に落としすぎると本当の動きも消える。**320×180 / 10fps が実用的な妥協点。**

### 判定ライン（実測値）

| 値 | 見え方 |
|---|---|
| **< 0.8** | フリーズに見える。**事故** |
| 2〜4 | 静かなホールド。グレインと微動で「生きている」 |
| 4〜8 | ゆっくりしたドリフト／パララックス |
| 10〜25 | 明確なカメラワーク・文字の横流し |
| 30〜60 | カット・ワイプ・インパクト |

参考にしたプロのタイトルシーケンスは、**最終ロックアップの完全静止区間ですら 2.0〜4.0** あった。プロの「止める」は完全な静止ではない。

### ショット単位で平均と最小の両方を見る
平均だけ見ると、頭のカットで数値が稼げて中身が死んでいても気づかない。**min が 0.8 を切るショットは必ず直す。**

```
shot          mine   ref     mine_min ref_min
s4 03:17      4.27   6.53      2.56    2.10   ok
s6 hold       0.01   3.97      0.01    2.02   ← フリーズ
```

### よくある原因と対処

| 症状 | 原因 | 対処 |
|---|---|---|
| ショット頭が0 | 前カットから引き継いだベタ面が全画面を覆っている | ワイプの進行度を0でなく0.15から始める |
| ショット後半が0 | イージングの終端で速度が0に漸近している | 等速成分を足す（`linear` のドリフトを常時1本重ねる） |
| ホールドが0 | グレインが効いていない | 下記「グレインが黒に効かない罠」 |
| 全体的に低い | カメラが無い（静止画の微パン/ズームすら無い） | レイヤーごとに違う移動量を入れる（→ type-behind-subject） |

### ★グレインが黒に効かない罠
`mix-blend-mode: overlay` は **base が 0 のとき結果も 0**（overlay は `2·base·blend`）。つまり**黒背景のホールドにはグレインが一切乗らない**。これで「グレイン入れたのに数値が0.01のまま」になる。

**正解: `screen` ＋ 平均輝度の低いノイズプレート。**
- プレート: 平均 26〜40 / 標準偏差 45前後、ミラー4分割でシームレス化
- 合成: `mix-blend-mode: screen`、opacity 0.07 前後
- 黒の持ち上がりは3〜5レベル（フィルムとして自然）

### ★細かすぎるグレインは縮小で消える
1px のノイズは 320×180 に落とすと平均化されて数値が立たない＝**視聴サイズでも見えていない**。
**粗い層（1920フレーム上で6px程度のクランプ）と細かい層を混ぜる。** 粗い層があると縮小後も残り、視聴時にもフィルムらしいクランプ感が出る。

### 参考動画がある場合
同じ指標で並べ、**ショットごとに ratio を出す**。0.5倍を切っていたら足りない、2倍を超えていたら動かしすぎ。
実例では、ある再現版で shot2 が参照の2.4倍（文字の横流しが速すぎ）、shot6 のホールドが参照の 1/400（フリーズ）だった。**どちらも目視では気づかなかった。**

## 注意点
- **フルHDのまま測らない。** グレインだけで数値が立って役に立たない
- **平均だけ見ない。** min を見ないとショット後半の失速を見逃す
- カット（不連続）は数値が跳ねるので、ショット境界の1〜2フレームは除外して読む
- 数値が高ければ良いわけではない。**参照と比べて2倍を超えていたら動かしすぎ**（うるさい）
- 完全静止が意図の場合（ストップモーション演出等）は例外。ただしその場合もグレインは乗せる

## 品質チェック
- 全区間で min ≥ 0.8 か
- ショット単位の平均が、参照（あれば）の 0.5〜2.0 倍に収まっているか
- 最終ホールドが 2.0 以上あるか（＝グレインが効いているか）
- 黒ベタ領域の輝度が 3〜5 に持ち上がっているか（screen グレインが乗っている証拠）

## バリエーション
- **レイヤー別測定:** 背景だけ／文字だけをレンダーして個別に測る。「文字だけ動いて背景が死んでいる」を検出
- **領域別測定:** 画面を3×3に割って測る。画面端だけ死んでいるのが分かる
- **オプティカルフロー版:** 差分でなく位相相関で dx/dy/scale を出す。「どっちにどれだけ動いているか」まで分かる（参照の再現時はこちら）
- **音との相関:** 音のトランジェント位置と差分ピークを並べ、音ハメのズレを見る
- **長尺の中だるみマップ:** 5分曲を1本のグラフにして、谷になっている区間を特定
