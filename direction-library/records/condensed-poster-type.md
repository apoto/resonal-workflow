# 超コンデンス・ポスター書体 / Condensed Poster Type

## 概要
極端に縦長・詰め組みの太いサンセリフで1〜2語を画面いっぱいに置く。フリーフォントの Anton を横に潰して字幅とステム太さを実測で合わせる。ノワール／ハードボイルド／ストリートの「格」はほぼこの1書体で決まる。

## 主な用途
- タイトルシーケンスのメインロゴ（HEADLINE / NO MERCY 等）
- サビの1語ドン（全画面1ワード）
- ジャケット・サムネの主見出し
- チャプター見出し／セクションタイトル

## 感情

## 難易度
★2（測って合わせるだけ。ただし**測らずに目分量でやると必ず外す**。測る手順を知っているかどうかの★2）

## 演出内容

### 1. 目標書体を「幅/キャップ高」で測る
参考画像のロゴを1つ選び、**単語の横幅 ÷ キャップ高**を測る。これが書体の詰まり具合の指紋になる。

| 書体 | 同じ7字の大文字1語の 幅/キャップ高 |
|---|---|
| 目標（参考画像のロゴ） | **2.23** |
| Anton | 3.39 |
| Oswald Bold | 4.18 |

→ フリーで一番近いのは常に **Anton**。他は候補にならない。

### 2. 横圧縮＋トラッキング戻しで合わせる
- 目標 2.23 ÷ Anton 3.39 ＝ **横スケール 0.63〜0.66**
- ただの `scaleX(0.63)` だと**字間まで詰まって**ベタっとする。**トラッキングを 0.03em 足して**から潰すと、参考のように字と字が離れた詰め組みになる
- 結果として **ステム（縦画）太さ＝キャップ高 × 0.13** に一致する（実測: 参考74px / 再現76〜80px、キャップ高572px）

**Anton のステム太さ早見:** `ステム px ≒ キャップ高 × 横スケール × 0.202`
狙いのステムから逆算して横スケールを決めてよい。

### 3. 巨大見出しは「拡大」ではなく「縦だけ伸ばす」
画面から上下がはみ出すレベルの巨大タイポは、**等倍拡大ではなく scaleY だけ 1.9〜2.0 倍**が正解。

- 等倍拡大 → ステムも太る → 「でかいだけの文字」
- **scaleY のみ** → ステム太さは据え置き → 「引き伸ばされた高級な見出し」

見分け方: 参考画像の巨大見出しと最終ロックアップで**ステム幅が同じ**なら縦伸ばし。実測では巨大見出しのステム75px＝最終タイトルのステム74px、キャップ高だけ2倍だった。

### 4. 画面外まではみ出させる
- 上下または左右が**必ず切れている**こと。画面に収まった瞬間に「字幕」になる
- 巨大見出しのキャップ高は **フレーム高の 1.15〜1.30 倍**
- 最終ロックアップだけは全体を収める（キャップ高＝フレーム高の 0.55〜0.60）

### 5. サブコピーは別ウェイト＋広いトラッキング
メイン1語の下に置く小さい行（短い英語のサブコピー）は、
- **Oswald 600**（メインより細い）
- **トラッキング 0.55〜0.60em**
- 幅をメイン見出しと**左右揃え**（同じ 1424px に収める）
- キャップ高はメインの **1/6**（639 : 103）

### 6. 質感
- 色は純白ではなく **ダーティアイボリー #EDE5D3**
- 紙／コンクリートのグランジを **multiply で薄く**（平均輝度0.92、最低0.66程度）。強すぎるとノイズに見える
- CSS で `background-clip: text` を使うとき、**`backgroundColor` と `backgroundImage` は混色されない**。色もグラデーションレイヤーにして `backgroundImage: url(grunge), linear-gradient(ivory, ivory)` ＋ `backgroundBlendMode: 'multiply, normal'` にしないと文字がグレーに転ぶ

### 7. 実装上の必須事項（Remotion / CSS）
**transform は layout に反映されない。** `scaleX(0.63)` した文字要素の**レイアウト幅は潰す前のまま**なので、flex 行に置くと隣の要素が画面外まで押し出される（2語を並べると文字同士が重なって別の綴りに読める）。

→ **外側の box に「潰した後の実寸」を明示的に持たせ、中の文字を絶対配置で中央に置く。**

## カメラワーク
- 固定が基本。文字自体を動かす（横流し・縦伸び）
- Push In を足すなら 3秒で +3〜4% まで

## 編集
- Smash Cut（この書体はカットで叩き付けるのが様式）
- 縦伸び＝赤い線から開く／閉じる、と組むと1本の線から生まれたように見える

## 色
- **メインカラー:** ダーティアイボリー #EDE5D3
- **アクセントカラー:** ブラッドレッド #F5000B
- **相性の良い配色:** 黒 + ディープチャコール + 赤 + アイボリーの**4色厳守**。5色目を入れた瞬間に格が落ちる

## ライティング
- なし（文字はフラット）。背景側の Neon / Rim Light と組む

## リリックとの相性
★2 — 日本語歌詞には使えない。**英語のキーワード1〜2語専用**。歌詞本体は別書体に任せる。

## AI画像生成で再現する場合
- **共通キーワード:** 生成AIに綴りを任せない。**文字は必ず後段で組む**
- **画像生成（providers.image）:** 「文字なし」で背景だけ作らせる（`no text, no letters, no watermark`）

## AI動画生成で再現する場合
- **重要要素:** 同上。AI動画に英単語を出させると綴りが崩れ、フレーム間で形も変わる
- **動画生成（providers.video）:** 背景・キャラの微動のみ担当。タイポは Remotion / AE

## 注意点
- **日本語に使えない。** 和文に超コンデンスの太い書体は存在しない（あっても可読性が死ぬ）。日本語は明朝/ゴシックに任せ、この書体は英字キーワード専用にする
- **目分量で潰さない。** 「幅/キャップ高」を測ってから決める。測らないと必ず太すぎ・広すぎになる
- Anton は横 0.63 まで潰しても破綻しないが、**0.55 を下回ると字形が壊れる**
- Anton はステムに対して字幅が広い設計なので、ステム太さを合わせると**単語幅は参考より約11%広くなる**。両方は一致しない。**ステム太さを優先**する（見た目の重さを支配するのはステム）
- `background-clip: text` ＋ `backgroundColor` はブラウザで混色されない（グレーに転ぶ）
- transform のレイアウト非反映（上記7）

## 品質チェック
- 巨大見出しと最終ロックアップで**ステム幅が同じ**か（違うなら等倍拡大してしまっている）
- 巨大見出しの上下または左右が**切れている**か
- 綴りが正しく、字間が均一か（潰した後に字が接触していないか）
- 色が純白になっていないか（アイボリーの温かみが残っているか）
- サブコピーがメイン見出しと**左右で揃っている**か

## バリエーション
- **アウトライン版:** 塗り無し＋1〜2pxストローク。カウンターから背景が見える（→ letterform-window へ）
- **ノックアウト版:** 赤ベタ面から文字を黒く抜く。ショット単位で反転させると打点になる
- **縦伸び→収束:** 1本の線から縦に開き、ベースに戻る。曲頭〜曲尾の対句に使える
- **左右ワイプ出し:** 赤い縦バーを先端に走らせながら左から出す（HEADL → HEADLI → HEADLIN → HEADLINE）
- **部分欠落からの充填:** サブコピーの文字をランダムに欠落させて出し、拍で埋める

## バリエーション: 1語の中で1文字だけ差し色／同じ語を2段
- 地は淡い面（クリーム `#eedfca`／青灰 `#c8d6da`）、塗りは黒・クリーム・差し色1色の3種だけ。縁・影・グロー無し。
- 1語のうち1文字だけ差し色（例: STOP の O）。同じ語を2段に重ね、下段をずらす。1画面1語・ハードカット・差し替えは拍ごと（参考の実測 中央値 0.18秒）。
