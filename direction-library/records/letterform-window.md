# 字面窓 / Letterform Window

## 概要
巨大な1文字を画面に置き、その**カウンター（字の中の空洞）だけを映像の窓**にする。文字の外側は黒で塗り潰し、字画はベタ、穴からポートレートが覗く。「文字＝フレーム」という宣言で、タイトルシーケンスで最も"デザインされて見える"1カット。

## 主な用途
- タイトルシーケンスのキメ（頭文字1字＋目のアップ）
- 曲名の各文字にキャラを1人ずつ割り当てる紹介カット
- 間奏の1カット勝負
- チャプター区切り（A / B / C を窓にする）

## 演出内容

### 必要な3要素（重ね順）
1. **映像プレート**（目のアップ等）
2. **黒 = 文字の"外周輪郭"の外側すべて**
3. **字画 = アイボリーのベタ**

結果:「外周の外＝黒 / 字画＝アイボリー / カウンター＝映像」。

### 実装の核心: 外周輪郭とフルパスを分けて持つ
テキスト要素からはこれが作れない。カウンターは常に穴として抜けており、「穴を含んだ外側シルエット」を取り出す手段が無いため。

**ビルド時にフォントからパスを抽出する。**
- グリフの輪郭を contour 単位に分解し、**面積最大の contour = 外周輪郭**、残り = カウンター
- `outer`（外周のみ）と `full`（全 contour, `fill-rule="evenodd"`）の2つのパス文字列を JSON に書き出す
- 抽出は fontTools（`RecordingPen` で contour 分割 → `SVGPathPen`）。書体ごとに `<font>-glyphs.json` として持つ

SVG での合成（knockout モード）:
```
<mask>  白い全面 rect ＋ outer を黒で描く   → 「外周の外だけ」
<rect fill=black mask=...>                  → 外周の外を黒で塗る
<path d=full fill-rule=evenodd fill=ivory>  → 字画をベタ塗り（カウンターは自動で穴）
```
フォント座標は Y-up なので `transform="translate(x y) scale(s*sx -s)"` で反転してベースラインを合わせる。

### 書体は「細字」を選ぶ ← 最重要
**タイトル書体をそのまま使うと失敗する。** 太い書体はカウンターが細いスリットで、窓として成立しない。

| 書体 | R のカウンター幅（em） | 窓として |
|---|---|---|
| Anton（タイトル書体） | **0.077** | 不可（ただの隙間） |
| Oswald Light (wght 300) | **0.234** | 可 |

→ **このカットだけ細字に差し替える。** タイトルが極太でも、窓のカットだけは細字にする。書体の一貫性より窓の成立を優先する。

### 窓に何を入れるか
- **目のアップ**が最も強い（視線が窓の中から出てくる）
- 顔全体を入れると「丸窓に人が映っている」だけになる。**目1つ**まで寄せる
- プレートのズームは元画像幅の **4〜7倍**。1456px級の素材だと甘くなるので、可能なら素材側を大きく作る

### 配置は「目標ボックス」から逆算する
サイズと位置を手で探ると必ず迷子になる。**外周輪郭の左右を画面上の目標 x に固定**して解く。

```
S  = (x1 - x0) / (outerX[1] - outerX[0])     // em サイズ
x0' = x0 - outerX[0] * S                      // グリフ原点
```
`x0: 430 → 58`、`x1: 1330 → 1860` とアニメーションさせれば、**ステムを画面左に固定したまま文字が育ち、カウンターが画面を覆っていく**。「字の中に入っていく」動きになる。

### E / N は「アウトライン」で作る
カウンターを持たない字（E, N, L, T…）は窓にならない。代わりに **塗り無し＋ストローク** で描くと、字画が細い枠線になって映像がそのまま見える。
- ストローク幅 10〜13px
- **`vector-effect="non-scaling-stroke"` を必ず付ける。** グリフに強い横スケールを掛けていると、ストロークが変形を継いで縦画だけ極太になる
- E は横スケール 3.0〜3.5 まで伸ばすと、字画が「編集デザインの罫線」に見える

## 色
- **メインカラー:** 黒（外周の外）＋ ダーティアイボリー（字画）
- **アクセントカラー:** 赤の細い罫線を字を貫通させて通す
- **相性の良い配色:** 4色以内

## ライティング
- 窓の中の被写体に強いキーライト／グロー（目の発光）。窓の外は完全な黒

## リリックとの相性
★1 — 歌詞は入らない。1文字の造形カットなので、**歌の無い区間**に置く。

## AI画像生成で再現する場合
- **共通キーワード:** 窓に入れる用の**極端な目のアップ**を別途生成しておくと画質が保てる。`extreme close-up of one eye, iris detail, glowing`
- **画像生成（providers.image）:** 素材段階で目のアップを1枚作るのが正攻法（元絵の拡大は甘くなる）

## AI動画生成で再現する場合
- **重要要素:** 文字は生成させない。窓に入れる目の微動（瞬き・虹彩の揺れ）だけ生成させる
- **動画生成（providers.video）:** 目のアップの微動ループ（瞬き・虹彩の揺れ）だけを短尺で作る

## 注意点
- **太い書体で試して「穴が細い」と気づかず時間を溶かさない。** 先に対象グリフのカウンター幅（em）を測る。0.15em 未満なら窓にならない
- **Remotion では SVG の生 `<image>` は delayRender に乗らない。** デコード前にキャプチャされて**カウンターが真っ黒**になる。プレートは SVG の外に通常の `<Img>` で置き、SVG は黒マスクと字画だけ担当させる
- ストロークに `vector-effect="non-scaling-stroke"` を付け忘れると縦画だけ極太になる
- グランジテクスチャを画面全面1枚で貼ると、字が巨大なとき数個の巨大なシミになる。**タイル（1000〜1200px）＋ミラー4分割でシームレス化**して敷く
- カウンターが画面より大きくなると「ただの黒帯2本」に見える。**外周の左右が画面内に収まる瞬間**を必ず1度は見せてから寄せる

## 品質チェック
- 「外周の外＝黒 / 字画＝ベタ / カウンター＝映像」の3領域が明確に分かれているか
- カットの序盤で**その文字が何の字か読める**瞬間があるか（いきなり寄っていると意味不明な図形になる）
- 窓の中の被写体が甘すぎないか（フル解像度で確認）
- アウトライン字（E/N）のストローク幅が縦横で均一か
- グランジのタイル継ぎ目が見えていないか

## バリエーション
- **複数字を並べる:** R / E / N を並べ、それぞれ別のキャラを入れる（登場人物紹介）
- **アウトライン版:** 全部ストロークにして映像を全面に見せ、字を罫線として重ねる
- **反転（ノックアウト）:** 字画に映像、外に黒、カウンターも黒。字が映像で塗られる逆パターン
- **窓が動く:** 文字を横に流し、窓が被写体の上を舐めていく
- **窓から抜ける:** カウンターを画面いっぱいまで拡大して、そのまま次カットの全画面映像に繋ぐ
