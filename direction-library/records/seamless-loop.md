# シームレスループ / Seamless Loop

## 概要
始点と終点が完全に一致し、無限再生しても継ぎ目が見えないループ素材の設計技術。演出というより「他の全ての微モーション演出を運用可能にするインフラ」。5秒のループが作れれば5分のMV背景・無限の配信待機画面になる＝制作コストを1/60にする量産の要。

## 主な用途
- MVの常時背景（1ループ素材を曲全体に敷く）
- 配信待機画面・Lo-fi系の流しっぱなし映像
- キャラクターの待機モーション（呼吸・揺れのループ）
- ビジュアライザーの背景レイヤー
- AI動画生成の5〜10秒制限を「無限尺」に変換する出口

- アウトロ（ループのまま音だけフェードすると「世界は続く」余韻）
- セクションごとに別ループ素材へ切り替えて展開を作る

## 演出内容
ループ化には3つの手法がある。**素材の運動の性質で選ぶ**のが正解で、万能の手法はない。

- **手法1: ffmpegピンポン化（正再生→逆再生連結）**
  ```
  ffmpeg -i in.mp4 -filter_complex "[0:v]split[a][b];[b]reverse[r];[a][r]concat=n=2:v=1[v]" -map "[v]" pingpong.mp4
  ```
  利点: どんな素材でも100%継ぎ目なし。失敗しない。
  欠点: 尺が2倍になる。**方向性のある運動が全部バレる**（上昇する粒が途中から降下する、歩きが後ろ歩きになる、煙が吸い込まれる）。
  適する: 揺れ・呼吸・明滅など往復対称の運動のみ。
  折返し点で1〜2フレーム静止が入ると「息継ぎ」が見えるので、逆再生側の先頭1フレームを削る（`reverse` 前に `trim`）と滑らか。

- **手法2: クロスフェードループ（末尾を先頭にフェード合成）**
  ```
  ffmpeg -i in.mp4 -filter_complex \
  "[0:v]split[v1][v2];[v1]trim=start=1,setpts=PTS-STARTPTS[main];[v2]trim=duration=1[head];[main][head]xfade=transition=fade:duration=1:offset=3[v]" \
  -map "[v]" crossloop.mp4
  ```
  （5秒素材の例: 本体=1〜5秒、先頭1秒を末尾にフェードで重ね、出力4秒。offset=本体尺−duration）
  利点: 方向性のある運動（粒上昇・雲・雨・流れ）を殺さずループ化できる。尺も増えない。
  欠点: フェード中は2つの時刻が半透明で重なるため、**輪郭の立った被写体（人物・文字）は二重像が出る**。フェード長は0.5〜1.5秒が目安（短いと跳ぶ、長いと重なりが見える）。
  適する: 粒・煙・水・光など「面」で動くテクスチャ的素材。

- **手法3: 始点=終点一致生成（設計段階でループを保証）**
  - **プロシージャル（Remotion/AE）:** すべての運動を `sin(2π × frame / 総フレーム数 × k)`（kは整数）で書く。周期が尺の整数分の一なら**数学的に完全ループ**。継ぎ目という概念自体が消える。自作モーションでは常にこれを最優先。
  - **動画生成（開始/終了フレーム指定）:** 開始フレームと終了フレームに同じ画像を指定し「元の絵→動く→元の絵に戻る」を生成させる。人物の微モーションループの現実解。
  利点: 尺そのまま・二重像なし・運動方向も自由。品質上限が最も高い。
  欠点: AI生成の場合、終点へ戻る際に**巻き戻し感・動きの失速**が出ることがある（その場合は手法1へフォールバック）。

- **ピンポン再生との使い分け（結論）:** 呼吸・髪揺れ・浮遊の往復＝ピンポンでOK。粒上昇・雨・雲・群衆・炎＝クロスフェード or 始点終点一致。自作プロシージャル＝常に手法3。AI生成人物＝手法3を試し、破綻したら手法1。
- **継ぎ目チェック:** 必ず `ffmpeg -stream_loop 3 -i loop.mp4 ...` で3周連結して実再生確認する。1周見ただけでは継ぎ目は評価できない。

## カメラワーク
- なし（固定）が原則。カメラが動く素材はループ化がほぼ不可能（位置が戻らない）
- 例外: orbit の360°1周をちょうど尺に収めたループ（3DCG/Remotionなら可能）

## 編集
- ループ素材の切り替えはセクション頭のビートに合わせてハードカット
- 同一素材の色違い（color-shift）を作ってセクション展開すると安く豪華に見える
- ループ周期をBPMに同期（例: BPM120で4秒=8拍ループ）させると音楽と噛み合う

## 色
- **メインカラー:** 制約なし（運用技術のため色非依存）
- **アクセントカラー:** 明滅系のアクセントはループ周期の整数分の一の周期で点滅させる
- **相性の良い配色:** 長時間見せる前提なので彩度・輝度は控えめが疲れない（Lo-fi系の教科書）

## ライティング
- 光の明滅・ネオンのフリッカーもループ周期に同期させる（sin設計なら自動で一致）
- 恒常光＋微弱な変動光の2層にすると「止まってないが、うるさくない」

## リリックとの相性
★★★★★ — ループ背景は歌詞演出の土台そのもの。背景が無限に持つので、前景の歌詞に全リソースを割ける。背景ループの周期とリリックの表示リズム（小節単位）を揃えると画面全体が音楽に同期する。

## AI画像生成で再現する場合
ループの元になる1枚を作る工程。動かしやすさを画づくりの段階で仕込む。
- **共通キーワード:** （画像自体はループと無関係。動かす前提の構図指定が本体）
- **画像生成（providers.image）:** 被写体と背景の分離が明確な画（暗背景×明るい被写体）を、最終動画と同じアスペクト比で作る（後トリミングは構図を壊す）。「candles flickering, particles in the air」など動く要素（髪・ネオン・粒）をはっきり描き込んでおくと、動画化時にその要素が自然に動く

## AI動画生成で再現する場合
5〜10秒制限のAI動画をループ化して無限尺にするのが現代の主戦場。
- **重要要素:** ①カメラ完全固定 ②往復・振動系の運動に限定 ③first/last frameの一致指定 ④「seamless loop」をプロンプトに明記
- **動画生成（providers.video）:** 終了フレームを開始画像と同じにできるなら本命。`subtle ambient motion, breathing, flickering neon, returns to the initial pose, seamless loop, static camera`、ネガティブに `camera movement, zoom, pan, scene change, walking`。
  終了フレームを指定できない／戻り際の失速が目立つ場合は、終了フレームなしで生成→ffmpegピンポンかクロスフェードで後処理する（運動を往復系に限定しておくとピンポン適性が上がる）

## 類似演出
- breathing-idle（ループさせる中身の代表。待機モーションそのもの）
- hair-cloth-sway（ピンポン適性が最も高いループ内容）
- particle-rise（クロスフェード/始点終点一致が必要なループ内容）
- floating-levitate（往復運動＝ループの模範生）

## 相性の良い演出
- breathing-idle（キャラ待機ループの中身として必須ペア）
- hair-cloth-sway（sin設計で完全ループ化できる筆頭）
- particle-rise（背景ループの定番要素）
- floating-levitate（上下往復はループと数学的に相性最良）
- neon-lighting（明滅周期をループ周期に同期させる）
- kinetic-typography（無限背景の上で歌詞に全リソースを割ける）
- color-shift（同一ループの色替えでセクション展開を安く作る）
- scanline-crt（走査線の周期運動もループに同期可能）
- frame-in-frame（小窓内で別ループを回す多層画面）
- light-leak（ゆっくりした光の往復はループ化が容易）

## 相性の悪い演出
- push-in（カメラが進むと位置が戻らない＝ループ不成立）
- speed-ramp（速度変化は周期性を破壊する）
- smash-cut（ループ素材内にカットがあると毎周同じ場所で跳ねてバレる）
- datamosh（フレーム間予測の破壊がループ点で必ず露呈する）
- camera-shake（ランダム揺れは始点終点が一致しない。sinベースの擬似シェイクなら可）

## RESONAL での使用例
- Killframe: 短尺クリップの尺を整数拍にスナップし playbackRate を微調整してタイルし、繋ぎ目を拍頭に乗せた。

## 注意点
- **1周だけ見て納品しない。** 必ず3周連結で継ぎ目を実再生確認（`-stream_loop`）。継ぎ目は2周目の頭で初めて見える
- ピンポンを方向性運動に使うと逆再生が即バレる（煙・粒・歩行・水流は禁止）。素材の運動の性質を先に分類する
- クロスフェードは人物・文字など輪郭のある被写体で二重像が出る。テクスチャ素材専用と心得る
- プロシージャルの周期は必ず「総フレーム数の整数分の一」に。59フレーム周期を60フレーム尺に入れると1フレームずつズレて数周後に破綻する
- ループの「うるささ」は再生時間に比例して効いてくる。5分間流す前提なら、単体で見て物足りないくらいの動きが正解

## 品質チェック
- ループ繋ぎ目が拍頭に一致している
- playbackRate 補正が±5%以内（動きが不自然にならない）
- 折返し（ピンポン）で動きの向きが破綻していない

## バリエーション
- **完全静止ループ（プロシージャル）:** Remotion/AEでsin設計。品質上限・コスト最小の本命
- **ピンポンループ:** 揺れ・呼吸素材の即席ループ化。制作30秒
- **クロスフェードループ:** 粒・煙・雲のテクスチャループ化。フェード1秒前後
- **AI始点終点一致ループ:** 開始/終了フレームに同じ画像を指定する方式。人物微モーションの現実解
- **BPM同期ループ:** 周期を拍数に合わせる（BPM120×8拍=4秒）。音楽との一体感が段違い
- **多層ループ:** 周期の違うループを3層重ね（背景8秒/中景5秒/前景3秒）、単調さを消す
