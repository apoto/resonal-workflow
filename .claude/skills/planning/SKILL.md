# 企画（案を出す → 人が選ぶ → BRIEF.md）

## 読むもの
1. profile/sound.md・profile/world.md・profile/character.md・profile/lyrics.md
2. profile/ledger.md（直近3曲と、表の下の `- メモ:`）
3. `songs/*/BRIEF.md`（台帳に無い曲もここで拾う）
4. `workflow.config.json` の `artist` / `vocalName` / `lyricsLang`

## 手順

### 1. 1問だけ聞く
「今回やってみたいことはありますか（テーマ・曲調・歌詞の言語・いつもと違う挑戦など）。無ければ『おまかせ』でOK」。
- ledger に `- メモ:` があれば「前にこう言っていましたが、どうしますか」と1行添える。

### 2. 案を2〜3本出して止まる
各案に次を並べる。1案に絞って持って行かない。
- 仮タイトル
- 一行コンセプト（この曲が一言で何か）
- ジャンル・テンポ（BPM の目安）・サビのムード
- 直近の曲との違い（テンポ／ジャンル／ムードのうち2つ以上を変える）
- 歌詞の切り口（誰が・どんな場面で・何を言う曲か）

最後に「どれにしますか。混ぜたい点や変えたい点があればそれも」と聞いて止まる。利用者の代わりに決めない。

### 3. 選ばれたら曲フォルダと BRIEF.md を作る
```bash
./next.sh --new "<Title>"     # songs/<YYMMDD>_<Title>/ と song.json を作る（手でフォルダを作らない）
```
`songs/<曲フォルダ>/BRIEF.md` を下のテンプレで書く。見出しの語は変えない（`./next.sh` が見出しで判定する）。

### 4. ledger に1行足す
profile/ledger.md の表に追記する:
```
| <Title> | <BPM 目安> | <ジャンル> | <ムード> | <一行コンセプト> |
```
- BPM は発注値。MV 工程で make_mv.sh が実測値に書き換える。
- 使った `- メモ:` は消す。

### 5. `./next.sh` を実行して企画工程が通ることを確かめる

## BRIEF.md テンプレ
```markdown
# BRIEF: <Title>

## 候補
### 案A: <タイトル>
- <一行コンセプト> / <ジャンル・BPM・ムード>
### 案B: <タイトル>
- ...
### 案C: <タイトル>
- ...

## 選んだ案
- 案<X>: <タイトル>（選んだ理由・利用者が足した注文）

## コンセプト
- 一行コンセプト:
- 語り手・場面・時間帯:
- 直近の曲との違い:

## サウンド
- ジャンル:
- BPM 目安:（発注値。実音源の実測値を正とする）
- ボーカル（声の質・歌い方）:
- 楽器・質感:

## 曲構成
- 例: A / B / サビ / 2番 A / B / サビ / 落ちサビ / ラスサビ。各ブロックの役割を1行ずつ

## 歌詞への申し送り
- 言語:（workflow.config.json の lyricsLang・profile/lyrics.md）
- 歌い手像と一人称:
- 入れたいモチーフ・避けたい言葉:

## ビジュアル
- カバー画像と MV の方向（被写体・配色・背景・時間帯）
```

## 規則
- 歌詞はここで書かない（skill `lyric-writing`）。
- 実在の曲のタイトル・歌詞・特徴的なフレーズを流用しない。
- profile と利用者の指示がぶつかったら利用者の指示を取る。恒久的な変更なら profile の更新を提案する。
