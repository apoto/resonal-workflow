# MV制作の実務ルール

実装・レンダー・検品に入る前に該当節を読む。

## テンポと拍
- 拍に同期させる演出（跳ね・面の切替・打点）を組む前に MV プロジェクトで `python3 tools/02_estimate_tempo.py <audio.wav> --out tempo.json` を回し、BPM と位相を区間別に実測する。発注 BPM は使わない。単一値の推定も鵜呑みにせず、別区間（サビのキック等）で独立に検算する。
- 拍のエンベロープ（`(sec * bpm / 60) % 1`）は sec=0 が拍頭という前提＝位相ゼロのまま渡さない。拍に乗せるもの（カメラ・FX・タイポの拍アニメ）には「音楽時刻」（位相とテンポ変化を補正した秒）を渡し、区間判定・歌詞の表示秒には実時刻を渡す。
- 検算: 各区間の拍頭で累積拍の端数が 0.02 拍以内か、drop の onset が拍頭に乗るかを数値で確かめてからレンダーする。

## 画の切替と歌詞の秒
- サビの面の切替・表情の切替・打点は、drop の拍頭ではなく歌い出しの語の実測秒に置く。関係するもの（セクション・シーン・振り付け・打点）を全部同じ秒に揃える。
- 秒は `round(t * fps) / fps` に丸めてから書く（格子外の境目は前後が1フレーム重なる）。
- 歌詞の秒は whisper の語オンセット（word timestamps）に吸着させる。セグメント境界だけで作らない。連呼・チャント区間は切り出して再転写する。
- 歌詞カードにあっても音になっていない語（合いの手・括弧書き）は画に出さない。
- スプリングで出るタイポは「表示開始」ではなく「決まる瞬間」（ピーク）を歌頭に合わせる。spring の config を変えたらピークのフレームを測り直す。

## 文字の大きさと階層
- 行幅から文字サイズを計算する（`04_build_lyrics.py` の計算を使う。自前で固定値を置かない）。書体を変えたら字幅の係数を測り直す（PIL の `getlength` ÷ (サイズ×文字数)）。
- 歌詞と画面固定 UI はカメラ変形（`transform: scale()`）の外に置く。見切れたらサイズより先に階層を疑う。
- `whiteSpace: nowrap` の要素は flex 中央揃えにせず、`left:50%; top:50%; transform: translate(-50%,-50%)` で中心を固定する。
- 文字幅を `canvas.measureText` で測るときは `document.fonts.check()` が true のときだけキャッシュする（未ロードだと代替フォントの幅が返る）。
- 「欧文か」の判定は ASCII 限定にせず「日本語を含まないなら欧文」にする。

## 縦ショート（9:16）
- 横の数字をそのまま渡さない。縦専用の値を持つ（散らし座標は中央の縦積みに、顔の帯を空ける）。
- 1〜2文字の巨大な語は上限だけ画面高基準にする（幅基準だと小さくなる）。
- 区間は音楽の切れ目で取る（サビの直前から歌い切りまで）。サビの途中で切らない。
- 本編とショートは両方焼いて見る（片方で良くてももう片方で壊れていることがある）。

## 暗背景のスタイルを明るい世界観へ振るとき
色を変えるだけでは成立しない。極性を反転する。

| 項目 | 暗背景 | 高明度 |
|---|---|---|
| 文字と背景 | 明るい文字 × 暗い背景 | 濃いインク × 明るい背景 |
| 縁取り | 暗い縁 | 白い縁 |
| スクリム・ビネット | 黒 | 白 |
| グロー | `mix-blend-mode: screen` | screen は白地で効かない＝低不透明の重ねに置換 |
| 打点 | 白/黒フラッシュ | 位置のズレ（registration slam / zoom-punch） |

## 素材（キャラ・背景）
- グリーンバックは色キーで抜く（rembg では抜けない）。キー色は実測する（左上 40×40 の平均）。similarity を上げすぎない。検査は「透過率」「残った緑」「緑でもないのに半透明な画素」の3つを数える。
- 動画の動きがおかしいときは、まず起点の静止画を疑う。立ち絵を直してから動画を作り直す。
- 素材の縦横比を変えたら、それを使う側の係数（拡大率・フレーミング）も一緒に見直す。拡大率は素材の占有率を実測して決める（手で1カットずつ合わせない）。
- 生成画像に形のある痕跡（足跡・文字）を描かせない。半透明のもの（湯気・煙）を色キー用の単色地の上に描かせない。

## Kling 素材
- 「流れる光」を `travel` / `flow` / `move across` で頼むと物体になる。背景を生かすなら `flicker` / `pulse` / `breathe` / `shimmer`（その場で明滅する語）で書く。
- 明滅・グレイン・走査線はコードで作る（Kling の明滅は輝度がほとんど動かない）。
- 止めるのは姿勢・構図・服・同一性だけ。呼吸・瞬き・髪・視線を止める語を入れない。
- Kling の出力は同じ絵が2フレームずつ続く（実質12fps）ことがある。連番化の前に隣接差を測って重複を間引いてから補間する。補間（RIFE 等）は色キーより前に掛ける（アルファが落ちるため）。

## レンダーと検品
- レンダー前に `df -h`（容量不足だとレンダラが壊れた mp4 を無言で吐く）。レンダー後は `06_verify.sh`（`make_mv.sh` 経由なら自動）。スタイルの README に別の検査があればそれも通す。
- 長いレンダーの前に 0.5 スケールか短い区間でフレームを確かめる。
- 検品は決まった時刻（尺の 10%刻み＋サビ頭＋クレジット区間）のフレームを `ffmpeg -ss <秒> -frames:v 1` で抜いて観る。縮小表示で判断せず、原寸クロップと画素の実測（`ffmpeg -f rawvideo`）まで見る。
- 書いた設計値は出発点であって、画の前では証拠にならない。「値が実装に渡ったか」は機械で、「その値が良いか」は画を観て決める。
- 割り当て（カットごとの素材など）を1か所ずつ直さない。全カットを一度に解き直す（前と重複せず使用回数が最小の候補を選ぶ）。派生する値は主の値から自動で導く。

## クレジット
- 文言は `workflow.config.json` の `credits`。一字一句変えない。
- 既定: 冒頭で1枚 2.5〜3.5 秒ずつ順番に。歌い出し前に終える。切替は小節頭。
- 可読性: 下スクリムはクレジット全区間で出しっぱなし（名前ごとに点滅させない）。上に小さく役割、下に大きく名前。はっきりした太い縁取りより、プレートとぼかした影で浮かせる。
- 検査: クレジット区間のフレームを原寸で抜いて、`credits` の文言が全部出ているかを目で確かめる（既定の型は `06_verify.sh` が配線を検査する）。
- 縦ショートは任意。
