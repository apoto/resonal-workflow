# MV の見せ方を選ぶ（13スタイル×18軸）

既定の MV は `tools/make_mv.sh`（spectrum-still）。このskill は利用者が見せ方を選びたいときだけ使う。

| 読むもの | いつ |
|---|---|
| [references/catalog.md](references/catalog.md) | 選定表を書くとき（13スタイルの見た目・向く曲の雰囲気・軸の既定・実装の場所） |
| [references/axes.md](references/axes.md) | 18軸を埋めるとき（STYLE-SELECTION.md の雛形もここ）／DIRECTION.md でシーン別の軸を書くとき |
| [references/practice.md](references/practice.md) | 実装・レンダー・検品に入るとき |

## 前提
- スタイルは RESONAL で使ってきたものをそのまま共有した実験的な資産。スタイルごとに手順や作りが揃っていない。選ぶ前に「既定の型より手間がかかり、手順が途中までのスタイルもある」と利用者に伝える。
- 音源はマスター済みの `<Title>.wav`。LYRICS.md と cover.png がそろってから選ぶ。

## 手順
1. 曲を測る: BPM・エネルギー・雰囲気（静か／明るい／暗い／壮大／切ない／攻撃的）。BPM は `python3 templates/mv/tools/02_estimate_tempo.py "songs/<曲フォルダ>/<Title>.wav"` で実測する（BRIEF の発注値は使わない）。
2. 歌詞を読む: 物語・感情・世界観・キーフレーズ・サビと drop の位置。
3. 選定表を書く（省略しない）。`ls styles/` で実物を確かめ、catalog.md の13スタイル＋既定の spectrum-still を1行ずつ評価して、採用1つ＋対抗1つに絞る。対抗を落とした理由も1行。
   - 「使ったことがない」「手順が少ない」は落選理由にしない（工数は選定表に書く）。
   - 直近3曲（profile/ledger.md）で使ったスタイルを選ぶなら理由を書く。
   - 曲の雰囲気と歌詞のテーマが別のスタイルを指すなら歌詞のテーマを優先する。
4. 18軸を1軸ずつ埋めて `songs/<曲フォルダ>/STYLE-SELECTION.md` に全部書く（雛形は axes.md）。既定のままの軸も「既定」＋理由を1行。冒頭に `MVスタイル: <採用>（対抗: <対抗>）` の行を置く。
5. 面／背景／被写体をどこから持ってくるかを同時に決める（静止画だけで済むか・動画生成が要るか・3D か）。静止画だけで組めるなら plate-swap を先に検討する。キャラ（C軸）はコストの小さい順（静止 → 表情差分 → CSSリグ → 動画生成）に検討する。
6. 選定表と18軸を利用者に見せ、採用を選んでもらって止まる。人の代わりに決めない。

## 軸の原則
- 各軸は1つだけ選ぶ。複数の決定を束ねた値を作らず、別の軸に割る。
- 18軸を毎回すべて検討して書く。「決めていない」と「既定にした」を区別するため。
- スタイルは軸表のプリセット。採用しても各軸は選び直してよい。
- STYLE-SELECTION.md の18軸は曲の既定値。シーンで変える軸は `songs/<曲フォルダ>/DIRECTION.md` の `## シーン別の軸` 節に `軸コード=値` で書く（記法は axes.md）。

## 演出の辞書から選んで実装させる
軸は「どの引き出しを開けるか」、`direction-library/`（演出73件＋場面19件）はその中身。
1. 軸ごとに、axes.md の選択肢に添えた辞書の slug か `direction-library/INDEX.md`（感情・タイミングで絞る）から候補を出す。場所から考えるなら INDEX の「場面」から入る。
2. 候補のレコードの「演出内容」「相性の悪い演出」「品質チェック」を読み、2〜3案を一行説明つきで利用者に見せて選んでもらう。
3. 選んだものを `songs/<曲フォルダ>/DIRECTION.md` に区間ごとに書く（`## シーン別の軸` の値と、カット表の行に slug）。
4. 実装はレコードの「演出内容」の数値どおりに、曲のプロジェクトの `src/` か `input/song.config.ts`（スタイルなら `styles/<名前>/` から作ったプロジェクト）を書き換える。辞書に無い数値を推測で足さない。
5. レンダー後、使ったレコードの「品質チェック」を YES/NO で確かめて利用者に伝える。

## 実装へ
- 採用が spectrum-still なら skill `music-video` の手順 1 に戻る（`tools/make_mv.sh`）。軸で変えたい点は `projects/<slug>/input/song.config.ts` で直す。
- それ以外は `styles/<採用>/README.md` を最初に読み、その手順に従う。README に無い手順を推測で足さない。分からない点は利用者に聞く。
- キャラを動かす部品は skill `bounce-rig`（拍で跳ねる）／`puppet-rig`（関節で折る）。カット割りは skill `mv-cut-editing`。
- 動画生成（背景・キャラの連番）は `providers.video` に従い、作る前に利用者に確認する（skill `music-video` の手順 0 と同じ扱い）。
- クレジット（`workflow.config.json` の `credits`）はどのスタイルでも必ず画面に入れる。レンダー後にクレジット区間のフレームを抜いて確かめる。
- 出力は既定の型と同じ名前で曲フォルダに置く（`<Title>.mp4` / `<Title> (Short).mp4` / `thumbnail.jpg`）。スタイルに縦ショートやサムネが無ければ、その旨を利用者に伝えて相談する。
- できたら skill `music-video` の手順 2（見てもらう）以降に合流する。

## スタイルを足す・改変する
13のスタイルはそのまま使ってよい。物足りなければ、利用者の指示で次の型に合わせて足す・直す。
- **新しいスタイルを足す**:
  1. 近い既存スタイル（または `templates/mv`）を `styles/<name>/` にコピーし、`package.json` の name を変える。
  2. `styles/<name>/README.md` に「見た目・素材・手順（コマンド）・出力」を書く。手順は既存スタイルの README と同じ見出しにする。
  3. catalog.md に `### N. <name>（ひとこと）` で足し、`実装:` `見た目:` `向く曲:` `向く歌詞:` `軸の既定:`（18軸の記法）を1行ずつ書く。
  4. 使った演出が辞書に無ければ、`direction-library/` に1件足す（`direction-library/README.md` の「レコードを足す・直す」）。
  5. `npm install && npx tsc --noEmit` を通し、短い区間でレンダーして見せてから利用者に確定してもらう。
- **既存のスタイルを改変する**: 曲1本だけの変更なら、曲のプロジェクト側（`input/` と `src/` の曲ごとの設定）で直し、`styles/` は触らない。全曲に効かせたいときだけ `styles/<name>/` を直し、catalog.md の該当行（見た目・軸の既定）を実装に合わせて書き換える。
- 色・画像名・曲名をスタイルのソースに書き込まない（曲ごとに palette と params で渡す）。キャラの動かし方はスタイルに足さず、rig 系 skill に足す。
- `styles/README.md` の一覧表にも1行足す（または直す）。
